## 一、问题现象

在 `online` 枢纽页新增"访问分项目"的入口选项（下载 / 音乐 / 游戏三张 hub 卡片）后，老版本浏览器打开 `online/` 时页面大面积空白，**三个分项目入口不可见、无法点击**；直接进入 `online/download/`、`online/music/`、`online/game/` 也存在样式错乱或部分内容不可见。

v8.4 曾修复过"变体重定向指向不存在文件导致 IE / Safari / 旧内核访问分项目入口 404"的问题（做法是移除子页的分流脚本），但移除分流后老浏览器直接落到了唯一一份使用现代 API 的页面上，**404 消除了，页面却依然不可用**。本次 Fix 解决的是 404 之后的这一层遗留问题。

受影响环境（典型）：IE8 / IE9 / IE10 / IE11、Safari 12.1 以前、Android 4.x ~ 5.x WebView、各类不支持 CSS 变量与 `classList` 的老内核。

---

## 二、根因定位

### 2.1 直接原因：内容可见性被绑定在"增强脚本必须成功执行"上

`online` 枢纽页的三张分项目入口卡片均带 `data-reveal` 属性：

```html
<a class="hub-card" href="download/" data-reveal> … </a>
<a class="hub-card" href="music/"   data-reveal> … </a>
<a class="hub-card" href="game/"    data-reveal> … </a>
```

而 `assets/online-base.css` 中该属性是**默认隐藏**的：

```css
[data-reveal]{opacity:0;transform:translateY(64px) scale(.97); …}
```

`assets/aesthetic.css` 还做了第二层隐藏：

```css
.fx-on [data-reveal]:not(.is-in):not(.fx-in){opacity:0; …; filter:blur(6px)}
```

也就是说，元素必须等 JS 给它加上 `.is-in` / `.fx-in` 才会显示。**隐藏规则是纯 CSS，在老浏览器上照常生效；解除隐藏却依赖老浏览器不具备的 JavaScript API** —— 这个不对称是问题的核心。

### 2.2 解除隐藏的脚本在老引擎上必然中断

| # | 位置 | 代码 | 老引擎表现 |
|---|---|---|---|
| 1 | `assets/aesthetic.js` 顶层第一条语句 | `t.classList.add("fx-on")` | IE9 及更早、旧 WebView 没有 `classList`，立即抛 `TypeError`；且**不在 try/catch 内**，整个增强层终止 |
| 2 | 各页 body 内联脚本 `$$()` | `Array.prototype.slice.call(...).forEach(...)` | IE8 无 `Array.prototype.forEach` |
| 3 | 同上 `themeBtn.addEventListener(...)` | 事件绑定段不在 try 内 | IE8 直接抛错并中断后续 `initReveal()` |
| 4 | 同上 `initReveal()` | `el.classList.add('from-below','is-in')` | IE9 无 `classList`；IE11 的 `DOMTokenList.add` 不接受多 token，`is-in` 可能加不上 |
| 5 | 同上 `catch` 兜底分支 | `$$('[data-reveal]').forEach(… classList.add('is-in'))` | 兜底代码本身再次调用 `forEach` / `classList`，**二次抛错，兜底失效** |
| 6 | `assets/aesthetic.js` 末尾 catch | `classList.add("fx-in","fx-done")` | 同样多参数 + `forEach`，失效 |

结果：`[data-reveal]` 永远停在 `opacity:0`，hub 卡片不可见，页面看似空白。

### 2.3 叠加因素

- **降级路径消失**：v8.4 为修 404 删除了 `online/download`、`online/music` 的分流脚本，老浏览器不再被导向专用变体，而是直接执行唯一一份现代脚本。
- **CSS 变量失效**：`.hub-card` 的 `color / background / border / border-radius / box-shadow` 全部使用 `var(--…)`。IE 全系与旧 WebView 不支持 CSS 变量，`var()` 所在声明整条被丢弃，卡片即使显示也缺乏底色与边框。
- **Grid 布局失效**：`.hub-grid{display:grid}` 在老内核被忽略，卡片退化为行内元素挤在一起。
- **入口链路不一致**：根 `index-ie.html` 的"在线"链接指向 `/online/index-legacy.html`，与 IE 专用变体 `index-ie.html` 不符。

## 三、修复方案（分层防御，纯增量）

设计原则：**现代浏览器零改动**；老引擎不再尝试执行任何现代代码，改为「静态内容优先可见 + 纯 ES3 基础交互」。

### L1 · 能力探测（`7` 个 online 页面 `<head>`，`charset` 之后）

新增一段 ES3 内联脚本，检测 `classList` / `Array#forEach` / `addEventListener` / `querySelector` / `CSS.supports` / `IntersectionObserver`，缺失即在 `<html>` 上打 `data-compat="legacy"` 标记。放在 charset 之后以保证中文注释不会乱码；不使用任何现代语法，任何浏览器都能执行。

### L2 · CSS 保险（`assets/online-base.css`）

追加 `html[data-compat="legacy"]` 作用域规则：

- 强制 `[data-reveal]` 与 `.section-head` 为 `opacity:1 !important; transform:none; filter:none; transition:none`，**彻底切断「必须靠 JS 才可见」的依赖**；
- `body` / 文字 / hub 卡片 / 下载卡片 / 导航提供不使用 CSS 变量的配色与边框兜底；
- `.hub-grid` 改 `display:block`、`.hub-card` 改 `display:block` 并让子元素块级堆叠，规避 Grid 与 Flex 缺失；
- 窄屏 `.nav-links` 定位用固定值兜底，展开卡片展开态 `max-height:none`。

### L3 · 增强脚本短路

- 每个 online 页面 body 末尾的内联增强脚本首部加入
  `if (document.documentElement.getAttribute('data-compat') === 'legacy') return;`，
  老引擎直接跳过全部现代代码，不再产生未捕获异常。
- `assets/aesthetic.js` 顶层加能力守卫：命中 `data-compat="legacy"` 或缺失 `classList` / `forEach` / `addEventListener` 时直接 `return`，避免在任何页面（含根页面变体）抛错。

### L4 · 新增 `assets/online-compat.js`（纯 ES3，零依赖）

老引擎专用交互层，仅在 `data-compat="legacy"` 时激活，不使用 `classList` / `forEach` / `querySelector` / `addEventListener` / `matchMedia` / `Date.now()` / Promise / CSS 变量：

1. **再次 inline 强制显示所有 `[data-reveal]` 元素**（CSS 之外的第二重保险，即使样式表加载失败也能看到入口）；
2. 恢复主题切换、可展开下载卡片、移动端菜单、回到顶部；
3. `document.body` 就绪判断 + `DOMContentLoaded` / `onreadystatechange` / `onload` 兜底，兼容忽略 `defer` 的 IE8；
4. 脚本置于 `</body>` 前且**不加 `defer`**，确保 IE8 也会执行。

### L5 · 入口链路修正

根 `index-ie.html`：`/online/index-legacy.html` → `/online/index-ie.html`，IE 用户进入与自身匹配的在线变体。

### L6 · 回归验证脚本 `tools/check-online-compat.js`

可重复执行的静态 + 行为双重校验，无需第三方依赖。

## 七、已知限制与说明

1. `legacy` 模式下**有意关闭**滚动显现、卡片倾斜、粒子、视差等增强动效；内容与入口链接为原生 `<a href>`，不依赖脚本即可点击。这是静态站面向老内核的预期降级，不是功能缺失。
2. `ppt/1/index.html` 的外链下载签名含 `X-Amz-Expires=300`（生成于 2026-10-31），属于外部对象存储的时效签名，现已过期。它不属于本次浏览器兼容性问题，未改动以免破坏用户原始内容，建议后续更换为长期有效的下载地址。
3. 当前环境无真机 / 真实老浏览器运行时，验证采用沙箱能力模拟（真实执行探测脚本与兼容层代码）+ 静态语法校验 + 资源可达性检查。上线后建议在目标老设备上做一次人工冒烟测试。
4. Git 标签不支持空格，故标签使用 `v8.4-fix`；Release 显示名称与本报告统一使用 **`v8.4 Fix`**。
