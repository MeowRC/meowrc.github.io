## 一、根因：降级条件被错误捆绑

项目现有的四个首页变体由 `<head>` 内的 UA / 能力分流决定。EdgeHTML 18（Edge 2019）与 Chrome 57~83 均通过 `isModern()`（要求 `display:flex`、CSS 变量、`transform`、`matchMedia`），因此进入**现代首页** `index.html`，仅依靠 `assets/compat-android7.css` 做 `@supports` 降级。

核查发现该降级层存在结构性缺陷：

> 把 **flex `gap`** 与**渐变文字扫光保护**放在 `@supports not (display: grid)` 条件块中。

EdgeHTML 18 与 Chrome 57~83 **支持 CSS Grid**，因此该条件为假，两项修复从未生效；但这些引擎同时**缺失** flex `gap`、`inset`、`clamp()` 与 `min()`，于是出现排版错误。

此外 `inset` 降级只覆盖 `.hero::after` / `.page-hero::after` / `.fx-grain`，遗漏了首页关键的：

- **`.navbar{inset:0 0 auto}`** —— 旧引擎整条声明失效，固定导航栏失去定位；
- `#loader{inset:0}`、`.hero::before`、`.hero::after`、`.hero-particles` —— 装饰层退化为 auto 定位；
- `clamp()` 遗漏 `.loader-logo`；`min()` 完全未覆盖（`.loader-bar`、`.footer::before` 宽度声明整条失效）。

## 二、修复内容

### 2.1 独立化每一项降级条件

`assets/compat-android7.css` 重写为 7 组互不依赖的条件：

| # | 属性 | 条件 | 说明 |
|---|---|---|---|
| 1 | `clamp()` | `@supports not (font-size: clamp(...))` | 补齐 `.loader-logo`，保留原 5 个标题 |
| 1b | `min()` | `@supports not (width: min(...))` | 新增 `.loader-bar`、`.footer::before` 宽度回退 |
| 2 | `backdrop-filter` | 独立 `@supports not` | 导航栏与主题控件改不透明背景 |
| 3 | CSS Grid | `@supports not (display:grid)` | 仅处理真正缺 Grid 的引擎 |
| 4 | `inset` | 独立 `@supports not (inset:0)` | 扩展至 12 个使用者，含 `.navbar` 特例 `bottom:auto` |
| 5 | flex `gap` | `html[data-no-flex-gap]` | 由运行时测量驱动，见 2.2 |
| 6 | `background-clip:text` | 独立 `@supports not` | 无裁剪能力时文字改实色，避免透明消失 |
| 7 | 渐变扫光 | `@supports not (display:grid)` | 保留原逻辑，不再承担 gap / 文字保护 |

### 2.2 运行时 flex-gap 探测

新增 `assets/compat-detect.js`（ES3 语法，同步执行于 `<head>` 最前，先于所有样式与其它脚本）。

CSS `@supports` 无法区分 grid `gap` 与 flex `gap`（旧引擎对 grid `gap` 返回真），因此该脚本创建一个真实的两项 flex 行并测量其间距：

- 间距 ≥ 9px → 原生 flex `gap` 可用，**不写任何标记**；
- 间距 < 9px 或布局 API 抛错 → 写 `data-no-flex-gap="1"`。

`compat-android7.css` 据此为 **20 个使用 `gap:` 的选择器**补回间距：行向容器用 `margin-left:10px`，列向容器用 `margin-top:14px`。该块对支持 flex `gap` 的引擎完全不生效。

### 2.3 全站接入与影响范围

- `compat-detect.js` 接入全部 11 个站点页面（4 首页变体 + 7 online 页），路径与顺序均经断言；
- 3 个纯跳转页（`pdf/1`、`ppt/1`、`ppt/2`）不接入——它们立即跳转、无渲染界面；
- 函数棋主体页不接入——独立 Canvas 应用与自有资源链。

**不受影响的路径**：桌面 Chrome / Edge 现代版 / Firefox、Safari 与 iPadOS、iOS 分档渲染（`data-ios-tier`）、Android 渲染预算（`data-perf`）、IE 专用变体（`index-ie.html`）、旧内核变体（`index-legacy.html`）。所有新增规则均由 `@supports not` 或 `html[data-no-flex-gap]` 门控，能力完整时零作用。

## 五、已知限制

1. **无 EdgeHTML / 旧 Chrome 真机**。验证基于能力条件静态核验、`compat-detect.js` 沙箱模拟与六套回归；建议在 Windows 10 自带 Edge 18 与 Chrome 70 上做一次人工冒烟。
2. `data-no-flex-gap` 依赖 `getBoundingClientRect`；若某引擎连该 API 都缺失，探测会保守地写入标记，走 margin 回退，不会更差。
3. 渐变文字兜底依赖 `@supports` 对 `background-clip:text` 的检测结果。若某引擎声明支持但渲染异常，仍可能出现标题颜色偏淡；本次未对这类引擎做 UA 特判，以保持"能力优先、无 UA 嗅探"的原则。
4. 本次只修复兼容性与可用性，未改变任何视觉设计、交互逻辑或内容结构。
5. `ppt/1` 的外链由服务方维护，其长期有效性不在本仓库控制范围内。
