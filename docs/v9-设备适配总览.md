## 一、关于「iPhone 9」的口径说明

需要先澄清一个事实：**苹果从未发布 iPhone 9**。2017 年 9 月苹果在发布 iPhone 8 的同期直接推出了 iPhone X，跳过数字 9，此后数字序列一直延续到 iPhone 16。

因此「iPhone 9 以上机型」在工程上无法按型号字面匹配。本次按行业通行理解处理为两种情况并同时覆盖：

1. **iPhone X 及之后的所有机型**（X / XS / XR / 11 / 12 / 13 / 14 / 15 / 16 全系，含 mini / Plus / Pro / Pro Max）；
2. **同时向下覆盖 iPhone 8 / SE2 / SE3**，使「8 之后」这一连续区间没有断裂。

实现上不依赖机型字符串匹配（iOS UA 不携带型号信息），而是用**屏幕物理像素面积**作为能力代理指标，见第三节。

## 二、全站设备支持矩阵

站点按浏览器能力分四个渲染变体，由 `<head>` 内的 UA/能力分流脚本决定；分流仅作用于首页与在线枢纽页，`download` / `music` / `game` 子页面按统一入口 + 条件层处理。

| 设备 / 环境 | 分流目标 | 渲染预算标记 | 关键适配 |
|---|---|---|---|
| Chrome / Edge / Firefox 桌面 | `index.html` | `data-glow="on"`（高性能时） | 完整视觉 + 条件式光效 |
| Safari 桌面（macOS） | `index-apple.html` | 同上 | Apple 专用 meta + 安全区变量 |
| IE8 ~ IE11 | `index-ie.html` | `data-compat="legacy"` | 静态 CSS、无 backdrop-filter、内容强制可见 |
| 旧内核（无 CSS 变量 / Grid） | `index-legacy.html` | `data-compat="legacy"` | 同上 + 简化布局 |
| Android 7+（Chrome 51~56） | 现代页 | `data-perf="mobile"` | `@supports` 降级 clamp / backdrop-filter / Grid / inset / gap |
| Android 手机 / 平板 | 现代页 | `data-perf="mobile"`，低配加 `-tier="low"` | 关闭极光/噪点/光球/持续动画，跳过增强脚本 |
| **iOS（iPhone / iPad）** | `index-apple.html` | `data-ios="1"` + `data-ios-tier="lite\|full"` | 安全区适配；lite 档关闭重型装饰 |
| iPhone 8 / SE2 / SE3 / X / XS / XR / 11 / 12 mini | `index-apple.html` | `data-ios-tier="lite"` | 关闭 4 层极光、光球、噪点、进度条、粒子、扫光；内容直显 |
| iPhone 12 / 13 / 14 / 15 / 16 全系、iPad 全系 | `index-apple.html` | `data-ios-tier="full"` | 完整视觉（仅全屏噪点层在全面屏设备上关闭） |
| Android TV / 桌面版 Android | 现代页 | 无移动标记 | 完整视觉 |

三个标记互斥且可组合：`data-compat`（老内核）、`data-perf`（Android 移动）、`data-ios-tier`（iOS 分档）。同一设备只会命中其中一条渲染路径，CSS 之间不会互相覆盖。

## 三、v9 本次改动：iOS 渲染分档

### 3.1 问题

v8.8 只做了 iOS 安全区适配，iOS 仍承载与桌面相同的全部装饰层：

- 4 个 `filter: blur(60px)` 极光层，30~48s 无限循环动画；
- 1 个 `blur(50px)` 光球，18s 浮动；
- 全屏 `feTurbulence` 噪点层 + `mix-blend-mode`；
- 13 处持续动画、`aesthetic.js` 的 22 个监听与 4 组 rAF 弹簧。

iOS Safari 对大面积 `filter: blur()` 动画的 GPU 开销同样显著，在 iPhone 8 / X / 11 等机型上会出现滚动掉帧与首屏延迟。

### 3.2 分档依据

iOS 不暴露 `deviceMemory`，Safari 的 `hardwareConcurrency` 也长期返回固定低值，因此改用**屏幕物理像素面积** `screen.width × screen.height × dpr²`：

| 判据 | 结果 |
|---|---|
| iPad（含 iPadOS 桌面 UA，短边 ≥ 744） | `full` |
| iPhone 物理像素 ≥ 2.9M（iPhone 12 及之后：2.96M ~ 3.78M） | `full` |
| 其余 iPhone（1.00M ~ 2.74M） | `lite` |
| `prefers-reduced-motion: reduce`（任意 iOS） | 强制 `lite` |

### 3.3 lite 档具体削减

| 关闭项 | 说明 |
|---|---|
| `.fx-aurora` / `.fx-hero-orb` / `.fx-progress` / `.fx-grain` / `.fx-sweep` / 粒子 / 光标 | 全屏或大面积 GPU 元素，直接不渲染 |
| 标题扫光、微光脉动、caret、scroll-hint 动画 | 停止所有无限循环动画 |
| `[data-reveal]` 的 `filter: blur(6px)` 与位移过渡 | 内容立即显示，不等 `IntersectionObserver` |
| `aesthetic.js` 增强层 | 顶层短路，不再创建装饰 DOM、不绑定监听、不启动 rAF 弹簧与 loader 轮询 |
| `will-change` 合成提示 | 收敛为 `auto`，减少离屏层显存 |

**保留项**：布局、渐变标题、卡片、导航毛玻璃、主题切换、移动菜单、展开卡片、回到顶部等全部功能与视觉骨架。

### 3.4 实现要点

- 分档写入 `data-ios-tier`，由 `ios-adapt.js` 在 `<head>` 内同步计算（ES5、无监听器）；
- `ios-adapt.css` 新增 20 条 `html[data-ios-tier="lite"]` 规则，全部带 `opacity:1 / filter:none` 兜底，确保增强脚本被短路后内容仍可见；
- `aesthetic.js` 顶层守卫增加 `data-ios-tier === 'lite'` 短路，与 Android 的 `data-perf` 处理保持一致。

## 七、已知限制

1. **无真机帧率采样**。iOS 分档通过 13 组画像模拟与 headless 渲染复核验证，实际提速幅度需在 iPhone 8 / X / 11 上以 Safari Web Inspector 实测。
2. **物理像素面积是能力代理，不是精确机型识别**。iOS 不提供可靠硬件信息，近似边界附近存在偏差，例如 iPhone 12 mini（2.27M）判为 lite、iPhone 12（2.96M）判为 full；两者视觉差异为「是否保留装饰动画」，不影响任何功能。
3. **lite 档为有意降级**：iOS 上会关闭极光、噪点、光球、扫光与视差，保留布局、渐变标题、卡片与全部交互。如需在特定机型恢复完整效果，可移除该机型的 `data-ios-tier` 或调整阈值。
4. `viewport-fit=cover` 使内容延伸至屏幕边缘，安全区留白依赖 `ios-adapt.css`；今后新增固定定位组件需同步补 inset。
5. iOS 只做渲染预算，不涉及 `mobile-perf.css`（该层仅识别 Android），两套层互不影响。
6. 本次未创建 Git tag / GitHub Release；`ppt/1` 的蓝奏云短链有效性由服务方决定。
